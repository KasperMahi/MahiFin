# Secure Cast integration decision

Status: bounded source investigation complete; **Jellyfin authorization/media loading remains blocked**. No Jellyfin credential was sent to a receiver. Existing sender SDK discovery and controls do not establish receiver security or media compatibility.

## Evidence

The audited [receiver main controller](https://github.com/jellyfin/jellyfin-chromecast/blob/43ab2aae4f1cadf3a7158b31d8b647e53f98c47a/src/components/maincontroller.ts) logs the incoming message with JSON serialization before processing it, then requires `serverAddress` and `accessToken` for the `urn:x-cast:com.connectsdk` protocol. Streaming/subtitle paths can carry `api_key`; the receiver also negotiates playback/conversion itself. A bounded recheck of the default-branch controller/helpers on 2026-10-15 still found message serialization and subtitle URL logging. This is source evidence, not proof of the revision deployed behind any receiver ID. Suppressing sender SDK logs cannot fix receiver logs or an independent receiver conversion decision.

## Required integration contract

1. Patch upstream or deploy an owner-approved receiver build. Replace message/URL serialization with allowlisted event categories. Cover accessToken, authorization headers, api_key query parameters, subtitle URLs, error reporting and third-party collectors. Test with sentinel secrets and assert they never occur in console output or exported telemetry, including malformed messages and failed loads. Do not copy GPL receiver source into the native app.
2. Make conversion policy explicit per load, item and source. Remux/audio paths must force video copy, preserve dimensions and reject burn-in/tone-map fallback. A receiver may request human consent via the sender before video encoding; acceptance must disclose the actual maximum dimensions/bitrate and HDR loss, be scoped/expiring, and be invalidated by item/source/profile changes. A sender boolean cannot authorize the receiver to select an unrelated source or silently choose a new profile. Test all resulting ffmpeg commands on the actual receiver/server combination. Unknown/older protocol versions fail closed for media loading.
3. Establish and document the actual authentication model. The audited protocol uses the Jellyfin user token; this project has not established a short-lived media-only receiver token endpoint. Do not invent one or treat a normal API key as scoped. Prefer a proven server-supported restricted credential if one becomes available, with expiry/revocation tests. Otherwise an explicitly approved, least-privileged account on a **verified safe receiver** still gives the receiver that account's privileges; disclose the boundary. A dedicated account does not make the current logging receiver safe. Any scoped-token gateway would require a separate server change/privacy review, not an implicit new service.
4. Obtain the registered receiver ID and attest the hosted source/build revision through the receiver owner. A configured ID alone is not evidence of safe code. Match its iOS Bonjour declaration and test local-network permission prompts. Receiver registration/hosting and any fees or owner permissions are external prerequisites; nothing is registered or paid for here.
5. With disposable credentials only, test launch/authentication, direct/copy/audio/explicit-video paths, denied consent, track change, seek/resume, pause/stop, reconnect/account switch, token revocation, failed load and encoding cleanup. Assert session/history ownership and never replay an old account envelope. Include legacy Chromecast hardware and HTTPS/certificate/network constraints. Inspect receiver logs privately for sentinels before permitting a real account.

Exit evidence must identify deployed receiver revision/ID, protocol/security tests, actual ffmpeg copy/consent outcomes and physical session-control results. Until then the native app retains its credential/load guard. No blanket receiver, codec, HDR or legacy-device claim follows from SDK compilation.

Distribution also needs the [Google Cast SDK terms](https://developers.google.com/cast/docs/terms), [iOS setup/local-network requirements](https://developers.google.com/cast/docs/ios_sender) and SDK privacy review described in [DISTRIBUTION.md](DISTRIBUTION.md). Owner authorization for a receiver change is a concrete blocker; further unrelated sender UI cannot resolve it.
